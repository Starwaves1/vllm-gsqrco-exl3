Finding that shaped the kernel: the vendored MMVQ already decodes each weight slice once per
activation row set. nvcc merges the per-column vec_dot decodes: the SASS of
mul_mat_vec_q<IQ3_S, n> (2 weight rows per CTA at n >= 2) has 70 / 106 global loads at n = 4 / 8
(+9 per column = one q8_1 block; weight and grid loads not repeated) and 64 / 128 IDP. So "decode once" alone is not a
lever; the per-column q8_1 loads, their reuse over only 2 weight rows per warp, and the decode's
instruction count are.
