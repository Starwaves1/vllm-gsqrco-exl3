R1: lossless load-time repack of IQ3_S / IQ3_XXS weights into the order the owned int8 tensor-core
kernel reads them (quantization/iq3_pack.py; kernel iq3_mma_packed in csrc/lcpp_owned_iq3_mma.cu;
op lcpp_mul_mat_vec_iq3_mma_packed). Branch opt-r1 from opt-k2 (197513b). Same microbench and box as
item 5 / K2 (bench/micro/gemm.py: op time per call incl. q8_1 quantize and output cast, 10 calls per
CUDA graph, bf16 X, real GGUF blocks, 350 W 3090). us at 17408 x 5120 / 5120 x 17408.

Why: K2's mma kernel and item 5's dp4a kernel are SM-bound, not DRAM-bound (K2: ~65 us with the
weights cache-resident vs a ~47 us DRAM floor). With 110 / 98-byte blocks, K2 staged each warp's 16
row windows through shared memory (8-byte loads, then ~46 2-byte shared loads per lane per block)
and spent ~4-5 ALU ops per 4-value word building its table index (qs byte + sign nibble + qh bit;
XXS: 7-bit group + popc parity).

Layout (bijective, same bytes per 16-row tile; tile t keeps the byte range of rows 16t..16t+15):
  one record per 16 rows x 1 weight block (1760 B IQ3_S, 1568 B IQ3_XXS; both 16-byte multiples)
  [0,1024)   lane (g,t) int4 x2: grid-index bytes of rows g and g+8, words 2t, 2t+1 of each slice
             (byte 2s+e = word 2t+e of slice s), i.e. the mma A fragment's k order (K2's order)
  IQ3_S [1024,1664): the 5 bits above each index (sign nibble | qh << 4) as 5 words per lane:
             20 words in the low 5 bits of the bytes, 12 in the bytes' top 3 bits
  IQ3_XXS [1024,1472): per (row, slice) the pair's 7 sign bits, re-coded so bit 3 = parity of the
             first word's nibble (bijective on 7 bits): the table then rebuilds both 4th signs
             (first word: bits 0-3, second: bits 3-6 -> T_odd); 14 bytes per lane, the 16th
             group's bits in the bytes' bit 7
  then per g: u32 sub-scale nibbles of rows g, g+8; then per g: half d of rows g, g+8
Kernel: K2's tiles, warps (4 splitting K), mma, integer sub-scales and fp32 order unchanged; the
lane fetches its 52 + 12 bytes per block with 6 (IQ3_S) / 7 (IQ3_XXS) coalesced loads straight into registers (prefetched
a block ahead), no weight staging; a word's table index is one prmt (IQ3_S: index byte + X byte +
a sign-replicated zero) or prmt + and (IQ3_XXS). Same 32 KB signed table (IQ3_S: K2's; XXS:
4096 first-word + 4096 second-word entries). 125 registers, 44 KB smem, 2 CTAs/SM.

Trade-off / open: the unpack is what MMQ (vendored, GGUF layout only) costs on packed W. The
task's other option, repacking only tensors whose every row count the owned kernels take, would
pack nothing today (prefill always reaches MMQ) and forfeit the decode gains. The unpack goes away
only if owned kernels take every row count of these tensors: a prefill-sized packed kernel
(activations staged once per CTA for a 64..128-row tile, as K3 is building for other types) with
this layout's decode. Until then: decode c=1/2/4 up, c=8 flat in ms/step, prefill -13 %, TTFT up.
